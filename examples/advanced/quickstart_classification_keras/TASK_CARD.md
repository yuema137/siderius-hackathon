# Task card: quickstart classification, Keras baseline (worked example)

This is a local walkthrough. It uses synthetic data to demonstrate the
package format, not a scientific contribution or a submission-ready challenge.

## Scientific question

Can a model recover a nonlinear decision rule from four noisy numeric features
with only 128 labelled rows? Each row has features x0..x3 drawn uniformly from
[-1, 1]; the label is 1 when x0*x1 + sin(pi*x2) > x3, with 3% of labels flipped
at random. The example stands in for any small tabular classification problem
where the rule mixes products and periodic terms.

## Task design

- One sample is one CSV row: `sample_id`, features `x0..x3` (float32), `label` (0 or 1).
- Model input `[B, 4]` float32; output `[B, 2]` logits (class 0, class 1),
  declared in `task/declared/task_config.yaml`.
- Splits by shard, fixed before any modelling: shards 0 and 1 form `train.csv`
  (128 rows), shard 2 forms `validation.csv` (64 rows), shard 3 (64 rows) is a
  held-out final test that `fetch_data.py` verifies but never places in the data
  folder. Shards are generated from independent random streams, so no row
  appears in two splits.
- `task/task.yaml` binds the data path (`train_file`, `validation_file`,
  `classes: [0, 1]`, `feature_count: 4`), the metrics and the Health checks.

## Data

- DOI: 10.5281/zenodo.ZENODO_RECORD_ID (intentional placeholder;
  data is generated locally, with no planned Zenodo publication)
- Size: 4 CSV files, 14,192 bytes in total; 64 rows per file
- License: cc-by-4.0
- Access: local walkthrough; the public-access declaration is illustrative
- Processing: `fetch_data.py` downloads the four shards (or reads them from
  `--source_dir`), checks each size and md5 against `data_source.json`, then
  writes `train.csv` (shards 0 and 1 concatenated) and `validation.csv`
  (shard 2) into `--output_dir`.
- Origin: generated by the SIDERIUS quickstart generator
  (`examples/quickstart/plugins/_quickstart_task.py`, seed 20260824); the files
  match the SHA-256 pins in that example's `declared/data_manifest.json`.

## Evaluation

- Primary metric `accuracy` (higher is better): the fraction of `validation.csv`
  rows whose predicted class equals the label. A row without a prediction counts
  as wrong.
- Secondary metric `balanced_accuracy` (higher is better): the mean of the
  per-class recall, so the 58% majority class cannot dominate the score.
- Health checks: `predicts_more_than_one_class` (blocking) rejects a model that
  predicts one class for every row; `dominant_class_fraction` (recording) flags
  a model that predicts one class for more than 80% of rows.
- Trivial reference: always predicting class 0 scores accuracy 0.578 (37/64)
  and balanced accuracy 0.5, and fails the blocking Health check.

## Baseline

- Method: Keras 3 MLP (Dense 16 ReLU, Dense 2 logits), Adam (learning rate
  0.01), batch size 32, 150 epochs, sparse categorical cross-entropy from
  logits, on `train.csv`. Keras runs on its PyTorch backend, which SIDERIUS
  already installs, so no TensorFlow download is needed.
- Score on `validation.csv`: accuracy 0.875, balanced accuracy 0.871872.
- Seed 20261104 (initial model and batch order); CPU only, one thread;
  about 6 s to train and 4 s to evaluate including start-up. No GPU needed.
- Saved as `baseline/init_model.keras` and `baseline/final_model.keras`.
  `baseline/requirements.txt` pins keras 3.12.0.
- The task package still ships the PyTorch MLP as its SIDERIUS model plugin:
  the plugin bonus is PyTorch-only, while the standalone baseline may use any
  framework.

## Novelty

None: this is a synthetic onboarding task, reused from the SIDERIUS quickstart.
A real submission names the closest public benchmark and what this task adds.

## Difficulty

Easy. The rule has three terms and only 128 training rows; with 3% label noise
the best achievable accuracy is about 0.97, so the baseline leaves roughly ten
points of headroom. The main risk is overfitting the small training set.

## Known shortcuts and leakage risks

- `sample_id` encodes the shard and row (`s2r017`) but not the label; the
  model input contains only `x0..x3`.
- Rows are not sorted by label, and the splits come from independent random
  streams, so there are no duplicates across splits.
- A majority-class predictor is caught by the blocking Health check.
